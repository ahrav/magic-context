# Pi synthetic todo provenance

Original Pi parity coverage documented one release-blocking gap independent of
current incident scenario code. Pi did not capture parent `todowrite` state in
`session_meta.last_todo_state`, inject a matching synthetic tool-use/result pair
on cache-busting materialization, replay a persisted anchor byte-identically,
or clear that anchor for terminal-only state. Subagent sessions had to remain
excluded from capture and injection while root-session capture remained active.

The deleted retained-red Bun suite was the original executable witness. Live
incident variants now exercise those assertions, but this document remains the
stable provenance source for `claim-pi-todo-synthesis-gap`.

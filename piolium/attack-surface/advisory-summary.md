### Recurring advisory signals

1. **Docs/build web stack is the historical hot spot:** Astro (25) and Vite (17) account for 42 of 52 advisories. Dominant classes are XSS/output escaping, URL/path canonicalization, SSRF, authorization/origin checks, and development-server file disclosure.
2. **Desktop IPC and local command boundaries have high impact:** the only Critical advisory is the historical Tauri shell scope-validation flaw. Current Tauri versions are outside the affected ranges, but the updater/process capabilities and `--serve` API deserve continued scrutiny.
3. **Agent-host supply chain is privileged:** Pi’s four recent advisories cluster around project-local extension trust, temporary installation paths, credential file permissions, and exported HTML. Magic Context itself loads as a host extension and can launch host plugin updates and subagents.
4. **Interpreter/model/native surfaces have weak advisory signal:** QuickJS, Transformers/ONNX, bundled SQLite, and Sharp/libvips process complex or executable inputs. An empty package-advisory result should not be treated as evidence of low risk.

## Architecture Hints

- **Products/processes:** published OpenCode and Pi/OMP extensions, a Node-based setup/doctor/migration CLI, a Rust `ck-mc` module under the `subc` daemon, a Tauri desktop dashboard, a standalone dashboard `--serve` HTTP mode, and a static Astro/Starlight docs site (`ARCHITECTURE.md`, `STRUCTURE.md`).
- **Durable data:** shared local SQLite at the CortexKit data path stores context history, memories, configuration-related state, migrations, and indexes. The desktop dashboard reads and mutates this store; Rust and TypeScript paths coordinate ownership and row-version/CAS state.
- **Local transports:** OpenCode plugin to TUI uses loopback HTTP/WebSocket RPC with a random bearer token in an owner-private port file (`packages/plugin/src/shared/rpc-server.ts`). TypeScript-to-Rust mode uses `@cortexkit/subc-client` and wire-v2 route handles. Tauri uses webview IPC.
- **Network surfaces:** model/provider and embedding egress; update checks/installers; docs deployment; smart-note HTTPS capability; and dashboard `--serve`. The dashboard server defaults to `127.0.0.1:9077`, applies Host/Origin/bearer/content-type guards, caps JSON at 1 MiB, and requires explicit `--allow-remote` for non-loopback binding. Remote mode still uses plain bearer-token HTTP and exposes write/subprocess-capable commands (`packages/dashboard/src-tauri/src/serve/mod.rs`).
- **Code execution/process launch:** QuickJS runs compiled smart-note predicates with explicit capabilities; CLI and runtime shell out to `git`, OpenCode, Pi/OMP, and database repair/install helpers; the auto-updater can invoke `opencode plugin <spec> --global --force`; Rust dashboard commands spawn local host tools.
- **Primary trust boundaries:** untrusted repository config versus user config; repository and conversation content versus LLM prompts; model-generated manifests/check code versus host capabilities; browser/webview content versus Tauri/dashboard commands; local processes versus bearer-token RPC; external embedding/model endpoints versus credentials and local data; TypeScript host versus Rust module authority.
- **Highest-value later review targets:** project-config trust filtering and secret inheritance, smart-note capability/SSRF/path fencing, dashboard `--serve` authentication and command dispatch, Tauri updater/IPC capability exposure, subprocess argument construction, auto-update package selection, SQLite authority/migration boundaries, and model-output parsers.

## Coverage Gaps

- **No Phase 2 work:** patch-commit discovery, compare diffs, bypass analysis, and commit archaeology were intentionally skipped as requested. The local git-message check was only a first-party advisory signal.
- **Web search unavailable:** the runtime’s `WebSearch` tool has no configured backend and `agent-browser` is absent. Structured GitHub, OSV, NVD, local source, and repository APIs were exhausted, but vendor blogs/mailing lists could contain disclosures not indexed there.
- **Identity ambiguity:** required identity resolution selects fork `ahrav/magic-context`; published packages point to upstream `cortexkit/magic-context`. Both GitHub repositories were queried, but future automation should preserve this fork/upstream distinction.
- **Direct-only dependency scope:** 71 npm/crates.io names were queried. The full transitive npm/Cargo graph, downloaded models, ONNX/native binaries, system SQLite/libvips, OS packages, and externally installed OpenCode/Pi/OMP binaries were not independently scanned.
- **Missing Rust sibling checkouts:** Cargo workspace metadata fails because `../commons` and `../subconscious` path dependencies are absent. Their names were inventoried from `Cargo.toml`, but exact source revisions and advisory status are unresolved.
- **Reachability is preliminary:** current Astro matches were checked against obvious config and source patterns only. No build, generated-site inspection, runtime reproduction, or framework-level reachability proof was performed in L1.
- **Package health/takeover analysis is shallow:** this pass identifies privileged and historically vulnerable dependencies, but does not exhaustively verify maintainer count, security contacts, release-signing, download trends, or repository ownership for all 71 registry components.
- **NVD coverage:** the project-name query returned zero results. NVD keyword searching every generic dependency name would be noisy; direct dependency intelligence instead used GitHub and OSV package identity queries, with NVD links/aliases retained where present.
